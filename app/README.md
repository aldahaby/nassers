# CITYBREAKER — app build

This folder exists for one reason: **haptics on iPhone**.

iOS Safari cannot vibrate. Not "not reliably" — at all. There is no Vibration API, and the one
workaround that exists (toggling a `switch` control) was tested on a real iPhone 14 and played
nothing, even when the switch was flipped directly by a finger. Add to Home Screen does not change
it either; that is the same WebKit under the same rules.

An app build can, and it is *better* than vibration — it plays real feedback styles rather than
buzzing a motor.

**The game needs no changes.** It already detects Capacitor and maps each event onto a feedback
style by itself.

---

## What you need

| | |
|---|---|
| **A Mac** | Xcode only runs on macOS. There is no way around this for an iOS build. |
| **Xcode** | free, from the Mac App Store |
| **Node.js** | 18 or newer |
| **An Apple ID** | free is fine to put it on **your own** phone — the app expires after 7 days and you re-run it. A paid Developer account ($99/yr) removes that and is required for TestFlight or the App Store. |

No Mac? Options, roughly in order of sanity: borrow one for twenty minutes; rent a cloud Mac by the
hour (MacStadium, MacinCloud); or use an Xcode Cloud / CI runner. Android needs none of this —
Android Studio runs on Windows and Linux and vibration already works there in plain Chrome.

## Build it

```bash
cd app
npm install
npx cap add ios          # first time only
npm run ios              # copies the game in, syncs, opens Xcode
```

Then in Xcode: pick your iPhone from the device menu, set **Signing & Capabilities → Team** to your
Apple ID, and press ▶.

The first run needs one extra step on the phone: **Settings → General → VPN & Device Management →
trust your developer certificate.**

For Android:

```bash
npx cap add android
npm run android
```

## Check it worked

Open **Settings** inside the game. The Vibration row should say **ON** with no note beside it.
If it still shows the greyed-out dash, the Haptics plugin did not install — re-run
`npm install && npx cap sync`.

## How the events map

The game does this mapping itself, in `Haptics._initNative`:

| Event | Feedback |
|---|---|
| `shard`, `tap`, `smashLight`, `closeCall` | impact **light** |
| `smashHeavy`, `power`, `combo`, `milestone` | impact **medium** |
| `smashHuge`, `powerBig` | impact **heavy** |
| `gateBlock`, `drone`, `death` | notification **error** |
| `fire`, `epic`, `ethereal`, `stage` | notification **success** |

To use a different shell (bare WKWebView, Cordova, anything), publish any one of these before the
page loads and the game picks it up automatically — see `ASSETS_HOWTO.md` for the full contract and
a WKWebView handler:

```js
window.CBHaptics = { play(name, pattern) { /* … */ } };
window.webkit.messageHandlers.cbHaptic.postMessage({ name, pattern });
window.CBAndroid.haptic(JSON.stringify({ name, pattern }));
```

## Notes

- `www/` is generated by `copy-web.mjs` and is **not** committed. `npm run sync` rebuilds it from
  `game.html`, `assets/` and `vendor/`, so the app always ships whatever is in the repo now.
- The web build at `aldahaby.github.io/nassers/game/` is unaffected by any of this and keeps
  working exactly as it does today.
- App Store submission needs more than this folder — icons, a launch screen, screenshots, a privacy
  manifest, and the IAP/ads wiring the Terms already describe. This scaffold is the haptics fix and
  a working starting point, not a finished submission.
