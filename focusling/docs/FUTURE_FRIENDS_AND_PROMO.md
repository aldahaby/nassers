# Future: Private Friends and the student launch offer (design contracts only)

**Nothing in this document is built.** No backend, accounts, friend codes, social screens, student
verification, ID capture or subscription code exist in the app. The only code is a set of
compile-time types in `src/core/models/future.ts`, which are deliberately **not** part of the save
(`core/__tests__/futureContracts.test.ts` checks that no friend or student data is stored).

## Private Friends (future V1)

> enter a code → mutual accept → see each other's Focuslings side by side → optionally a small set of
> positive weekly focus metrics.

- **Codes:** random, generated by the server, rotatable and revocable; never derived from email,
  school, phone, name or pet name. Code or QR initiated only.
- **Shared fields:** `FriendProfilePreview` is the whole boundary: pet name, species, stage, equipped
  cosmetics, favourite reaction, room colour, and opt-in weekly totals.
- **Never:** public directory or search, contact scraping, location, exact session timestamps, DMs,
  feeds, follower counts or global leaderboards. Remove and block are always one tap.
- **Not a paid feature:** basic friend comparison stays free; premium may only add personalisation
  around it.
- **Before building, decide:** what creates an account; authentication (Sign in with Apple, email,
  passkeys); the exact cloud-visible fields; age handling and abuse prevention; in-app account and
  data deletion (required by App Review as soon as accounts exist).
- **Child View:** Friends does not ship there until an explicit age/consent/privacy decision is made.

## College student launch offer (future)

> verified college student → first month free, delivered as a StoreKit offer.

1. The user chooses "Verify student status".
2. Any ID or document goes only to a chosen verification provider (or a short-lived secure endpoint).
3. Focusling receives and stores only the result: `StudentPromoEligibility` (status, provider,
   reference, dates). **No ID image is ever stored in app state** (the type has no field for one).
4. Eligible users redeem a one-time, auditable StoreKit subscription offer (e.g. an offer code); the
   iOS app never unlocks paid features outside In-App Purchase.
5. Update the privacy policy and App Store privacy answers before launch.

## App Review hygiene to carry forward

- Screenshots show the shipping build; no broken demo flows, dead links or "coming soon" dead ends.
- Once accounts exist: working review access and in-app account deletion.
- Once purchases exist: StoreKit for digital features and a Restore Purchases path.
- An accessible in-app privacy-policy link and accurate App Store privacy answers at all times.
- Don't describe the app as "for kids" in metadata unless it deliberately joins the Kids Category.
